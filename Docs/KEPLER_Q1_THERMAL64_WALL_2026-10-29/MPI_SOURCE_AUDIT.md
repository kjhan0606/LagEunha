# Existing native MPI paths and thermal64 wall limitations

The user code still contains MPI migration and halo infrastructure. `Exam/mpirks.exam2d.c` calls `pmigrate` with `TVORORK4_DDINFO`, and `paddingTreeVorork4Particles` calls `ppadding` with the same descriptor. `RkS/mpirks.c::ppadding` uses `ddinfo->n_size` for each particle copy before its padding exchange. `Exam/exam_gpu_extract.c::fillParticleSoA` copies the stress fields used as thermal64 U/V/RHS/tag/anchor into the host GPU arrays, and its ordinary post-gradient halo refresh repads full records before uploading again. These source observations are not a real multi-rank payload or CUDA correctness test.

The current thermal64 dispatch (`Exam/gfs_thermal64_native.inc`) requires `NID==1`; the fixed-wall transaction (`Exam/gfs_wall_events.inc::gfs_wall_begin`) independently rejects `NID!=1`. Its saved wall totals and event decision are local. `gfs_wall_valid` can branch to a retry locally, while subsequent native code invokes MPI collectives. Simply removing the guards would therefore not provide collective agreement on acceptance, earliest wall event, global timestep, owned-ID migration, wall impulse or energy, and can cause ranks to take different control paths.

The existing `gfs_ssp_restore` does save/restore each rank's full local particle body and invalidates that rank's GPU cache; `gfs_ssp_valid` demonstrates an MPI reduction for a validity flag. Those are useful existing building blocks, not proof that the thermal64 wall transaction is distributed. In particular, some existing SSP call sites short-circuit a local `gpu_geometry_trial_failed()` before calling the collective validator. A new distributed path must make every rank execute matching collectives even when only one rank sees a geometry failure, then restore or commit collectively; it must not copy that short-circuit control flow.

Required evidence for a future implementation includes real 2+ rank native migration and halo checks for authoritative U64/V64/RHS/tag/anchor, face-pair symmetry and energy work, a rejection injected on only one rank with exact global restoration and no collective hang, global earliest-event selection and wall budgets, restart continuity and 1-vs-multi-rank force/trajectory comparisons. Preserve the one-rank path and the current guards until those checks pass. This audit performs no new MPI run and does not claim an MPI implementation or performance result.
