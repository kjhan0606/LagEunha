# 자문 요청 (3차): GIZMO 입자판 Kepler 원반에서 방식 (1)의 붕괴 — 원인과 그 구현의 필요성

작성: 2026-09-30, LagEunha(LagForce) 작업 세션.

**사용자 원칙: 패치로 대응 금지.** 증상을 막는 한도, 바닥값, 클램프, 허용오차 완화, 벌점, 시간간격 조건 추가를 권하지 말고, (1) 원인, (2) 그 원인이 된 구현이 왜 들어갔고 지금도 필요한지를 먼저 판단해 주십시오. 권고는 그 판단 위에서만 해 주십시오.

## 1. 시험

- 목적: 인공(수치) 점성이 차가운 Kepler 원반을 얼마나 망가뜨리는지 잰다.
- 초기조건: Hopkins 2015 §4.2.4의 **입자판**(GIZMO). 64² 정규 격자를 −2<x,y<2에 깔고 0.5≤r≤2만 남긴다. Σ=1, P=10⁻⁶, γ=5/3, 원궤도 속도 `v=r(r²+ε²)^{-3/4}`, ε=0.01, 자체중력 없음. 진공 안팎, 바닥 밀도 없음.
- 코드: C `eunha2.exe`, 방식 (1)(GFS, Voronoi W=0, MUSCL+HLL/HLLC, RK4, `SEDOV_PHASE1=1`, 쌍 압력과 일 한도, 극단 면 처리).
  - 브랜치 `claude/gizmo-kepler-particle-ic`(로컬): `5874fe6`에서 IC 옵션 `EUNHA_KEPLER_PROFILE=gizmo` 추가. `64716f5`, `cc565b3`에서 셀 상한을 `VORO_CELLBOX`로 변경(아래 §2).
  - 상자 [0,6]², 중심 (3,3), Nx=96(Δx=1/16), 4랭크, A40 GPU 1장.
- 분석: `Docs/analyze_kepler_gizmo.py`.
- 실행 디렉터리: `/gpfs/kjhan/LagForce/Kepler_GIZMOparticle_S1_eff64_*`.

## 2. 관측과 이미 확인한 원인

**A. 셀 상한이 사실상 없었다(`5874fe6`, 실행 408978).**
- 셀 초기 다각형의 변은 `BOXSIZE/NX×5`다. KH 모델은 `Boxsize`를 읽지 않아 기본값 512를 쓴다. 이 실행에서 상한은 26.7로, 상자보다 컸다.
- 바깥 진공 가장자리 셀이 격자 셀의 164배까지 커지고, 정사각형 상자 모양을 따라 궤도 방향으로 부피가 약 2배 요동했다. 긴 면(최대 2.2)이 생겼다.
- 바닥값 에너지의 100%가 r>1.9에서 생겼고, t≈2.7(r=1 기준 0.43궤도)에 NaN이 되었다.
- 수정: KH 모델에서는 `(SIMBOX x 범위)/NX×5`를 쓰도록 했다(사용자 합의). 그 뒤 바닥값 폭주는 사라졌다.

**B. `EUNHA_KEPLER_DTETA=0.06` 시간간격 조건**(Grokbot `1b6155a`, 기본값 0, 옛 잡 스크립트에서 복사)
- 조건은 `dt ≤ η(R²+ε²)^{3/4} = η√(R/|a|)`다.
- 5Δx 상한 실행(408990)에서 안쪽 가장자리 입자가 t≈4.5부터 반경 0.3 아래로 떨어져, t≈6.3에 R≈0.005에 도달했다. 그 뒤 전체 dt가 `η·ε^{1.5}=6e-5`로 떨어졌다.
- t=6에서 측정한 것:
  - 총각운동량 변화 +2.9e-5(보존)
  - 원반 본체(r=1–1.75)의 L_z 변화는 1e-6 수준
  - 안쪽 가장자리(0.5–0.6)는 L_z가 −0.10, 바로 바깥(0.6–0.75)은 +0.10
  - 바깥 가장자리 1.9–2.0은 −0.88, r>2는 +0.34
  - 공동에 들어간 입자 4개의 v_φ/v_K는 0.72–0.96
  - 원반 안에서 전단으로 가까워진 쌍이 130개, 최소 거리는 격자 간격의 1/26
- **η를 끈 실행(409009):** dt가 CFL로만 정해져 0.05–0.07이 되었다. 가장자리 입자가 중심에 들어간 t≈5.5–6.0에 중력과 유체 RK4 잔차가 폭발했다(rkp +1.09, rkh +1.95, dE +0.62). 입자가 튕겨 나가 원반을 무너뜨렸다(t=12에 질량 절반 이상이 r>2).
- 이 조건은 가속도 기반 표준 조건과 같아 **필요하다**고 판단했다. η를 끈 것은 잘못이었다.

**C. 옛 초기조건(1/R 프로파일, 공동에 바닥 밀도 입자) 측정**
- Python 프로토타입 64²에서 바닥값 에너지의 82%가 R<1, 18%가 1–2에서 생겼다. 원반 본체의 기여는 0.1%였다.
- 코드(256²) 실행들도 t≈0.9부터 dt가 약 6e-4로 떨어진 채 돌았다.

## 3. 방식 (1)에서 소산을 만드는 항과 출처

| 항 | 도입 커밋 | 비고 |
|---|---|---|
| 쌍 압력 `P0 = 16ρ̄(c̄² + min(v_close², c̄²))(1−d/d_c)²`, `d_c = 0.2·min 길이` | 초기(`79af847`에서 상한), `b3cf6fa` 일 한도, `056ee76` 예산 변경 | 인수인계서: "충격용 인공점성이 아니다". 가까운 쌍이 400개 넘게 걸림 |
| Riemann `P*`: `hll_star_state`(HLL 평균 보존량에서 EOS로 P) | `056ee76`(풍상 선택 제거) | Lax 단조성 위반이 보고됨(1차 자문, 무작위 표본 21%) |
| 극단 면(`P_max > 100 P_min`)에서 HLL `v*` 사용 | `5f2fb86` 등 | 진공 가장자리에서 빈번할 것 |
| 셀 상한 `VORO_CELLBOX` | 이번 세션 | 진공 가장자리 셀을 5Δx 정사각형으로 자름. 잘린 변은 이웃이 없는 면 |
| 면 일에 쓰는 속도(회전 항 포함) | `5f2fb86` "Keep GFS face work consistent with the mesh" | 회전 항의 일이 소산으로 새는 경로(정식화 문서 §2) |

## 4. 질문

1. **안쪽 가장자리 입자가 약 2궤도 만에 각운동량을 잃는 원인**을, 위 항들 가운데 무엇이라고 보는가? 코드(`Exam/exam.c` 면 루프, `Exam/gfs_pair.h`, `hll_star_state`, 극단 면 분기)를 읽고 판단해 달라. 진공 가장자리와 전단이 어떻게 작용하는지도 포함한다.
   - 이것을 **패치 없이** 판별하는 측정을 설계해 달라. 예: 항을 하나씩 끄는 짧은 실행, 면별 토크 장부, 스냅숏 분석.
2. 각 항은 **왜 들어갔고 지금도 필요한가?** 특히 쌍 압력(무엇을 막으려고 넣었는지, 차가운 전단 원반에서 무엇을 하는지), HLL 평균 `P*`, 극단 면 처리, 셀 상한 5Δx(상한 자체가 필요한 설계인지, 잘린 변을 어떻게 다뤄야 하는지).
3. **시간간격:** `dtETA` 조건은 필요하다는 판단에 동의하는가? 전역 시간간격에서 입자 하나가 전체 dt를 결정하는 문제를, 패치 없이 다룰 원리적 방법은 무엇인가? 개별 시간간격 외의 대안이 있는가?
4. **진공 가장자리:** 입자 = 생성점 Voronoi에서 진공 경계를 어떻게 다루는 것이 원리적으로 맞는가? 상한으로 잘린 셀의 경계 면(이웃 없음)에서의 힘과 일을 코드가 어떻게 처리하는지 확인해 달라.
5. **공정한 인공 점성 시험 규약:** 이 코드(전역 dt, 입자 = 생성점)에서 GIZMO 비교가 의미를 가지려면 무엇이 필요한가? 지표와 판정 기준도 제안해 달라.
