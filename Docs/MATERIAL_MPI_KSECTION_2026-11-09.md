# Native material SSPRK2: k-section MPI qualification

사용자 승인: 현재 단계 커밋·푸시 및 모든 기존 material SSPRK2 경로의 nrank>1 구현. 영역 분할에는 사용자가 만든 k-section DD를 사용한다. 실행 중인 KH/GIZMO 동결 바이너리는 교체하지 않는다. 다음 과학 단계는 별도 승인 대상이다.

## 구현 범위

`Exam/NativeU64/gfs_material_mpi.inc`는 기존 `mpirks`와 `migrateTreeVorork4Particles` → `pmigrate`를 호출한다. `Exam/NativeU64/mpirks.exam2d.c`와 `RkS/`의 예제·분할 자료를 재사용한다. 별도 stripe/ID-modulo 분할은 없다. 3랭크 시험도 포함했다.

지속 상태는 각 랭크가 소유한 입자이며, 연산 시 ID로 정렬된 전역 상태와 제약 그래프를 구성한다. GPU 셀 기하 계산은 k-section 소유자가 담당하고, 각 행은 소유자 한 곳에서만 모은다. 전역 압력·가중치 제약은 0번 랭크에서 풀고 RHS·CFL·부피 보정·에너지 장부를 방송한다. 모든 랭크가 같은 SSPRK2 단계와 거절/복구 결정을 내린다. 승인된 스텝 이후 기존 `pmigrate`로 소유권을 갱신한다. 복구 중에는 이주하지 않는다. 출력 전 물리 상태와 uint64 ID의 해시를 대조한다.

지원된 기존 native 2D 경로는 KH, RT, Sedov, Noh, 원통, Gresho, 주기 Sod, 주기 전단이다. 1D 연구용 프로그램이나 3D 시간진화를 새로 MPI화했다는 뜻은 아니다. 기존 고정질량, 경계 힘·일, 부피 역산, SSPRK2 물리식은 유지했다.

원통은 유입/유출 ID와 외부 상태 장부를 동일하게 처리한다. 새 ID는 일단 0번 랭크에서 소유하고 기존 k-section 이주를 적용한다. 체크포인트 본체는 기존 집합 I/O, 경계 sidecar는 0번 랭크 쓰기 후 동기화다.

**성능 한계:** 전역 상태·기하 그래프가 랭크마다 복제되고 제약식은 한 랭크에서 풀린다. 메모리는 랭크당 O(N)이며 Allgatherv 총 payload는 INT_MAX bytes 이내다. 이는 nrank>1 기능 구현이지, 완전한 분산 메모리/가속 완료가 아니다. 작은 KH 21스텝은 1랭크 2.74초, 4랭크 4.15초로 오히려 느렸다(프로세스 시작 포함). 원통 65스텝은 48.4초/69.6초였다. 현재 장시간 작업을 이 구현으로 교체하지 않았다.

## 실제 실행 검증

작업 경로: `Research/MaterialVolume_20261105/material_pressure_acceleration_20261107_v1/mpi_ksection_20261109_v1/`.
Syntax A10 두 장에서 1 OpenMP thread/rank, 최대 4 MPI ranks(카드당 2랭크)를 사용했다. Ada에서는 1·2랭크 검사를 수행했다.

| 검사 | 해상도/셀 수 | 랭크 | 결과 |
|---|---:|---:|---|
| KH 짧은 진화 | 32×64 | 1,2,3,4 | 13개 저장 항목 bitwise 일치 |
| RT 짧은 진화 | 64×128 | 1,2,3,4 | 동일 |
| Sedov 짧은 진화 | 32² | 1,2,3,4 | 동일 |
| Noh 짧은 진화 | 32² | 1,2,3,4 | 동일 |
| 원통 짧은 진화 | 7,912 | 1,2,3,4 | 동일 |
| 위 다섯 경로의 MPI 변경 전 바이너리 대조 | 동일 IC·시각 | 1 | 저장 물리 항목 bitwise 일치 |
| Gresho / Sod / 전단 | 64² / 32² / 32² | 1,4 | bitwise 일치 |
| KH 21스텝 | 32×64 | 1,4 | bitwise 일치 |
| Noh 부피 `stages` 모드 | 32² | 1,4 | bitwise 일치 |
| 원통 t=0.250275→0.350525 | 7,912 | 1,4 | 65스텝, 40개 유입·40개 유출, bitwise 일치 |
| 4랭크 KH 체크포인트를 다른 랭크 수로 재개 | 32×64 | 1,2 | 최대 차이 3.45e-14(가속도); 질량·ID 동일 |
| 4랭크 원통/sidecar 재개 | 7,912 | 1,2,4 | 최대 차이 1.29e-13(가속도); 질량·ID 동일 |
| predictor 이후 강제 1회 거절/복구 | 32×64 KH | 1,4 | `retries=1` 확인, 최종 상태 bitwise 일치 |

비교 항목은 x,y,vx,vy,ax,ay,mass,U,V,W,pi,inertia,ID이다. 랭크별 기록 순서는 달라지므로 ID 정렬 후 비교했다. 체크포인트 파일 자체의 hash가 같다는 뜻은 아니다. 모든 저장 상태에서 유한값, 양의 질량·열에너지·부피와 ID 중복 없음을 확인했다. 재시작 차이는 roundoff 수준이며 이를 bitwise 동일이라고 표시하지 않는다.

실제 원통 출입 검사에서 에너지 장부 잔차는 1랭크 -8.64e-15, 4랭크 -1.54e-15였다. 기존 벽 접촉 에너지 항은 별도이며, 총 변화 -1.02e-4를 물리 에너지 보존 1e-15로 오인하면 안 된다. 이번 검사는 기존 경계 연산자의 MPI 동등성이다.

증거: `short_comparison.json`, `qualification_report.json`, `collect_qualification.py`. 보고서에는 입력 체크포인트와 실행 바이너리 hash, 종료 상태, 도달 시각, 출입 로그, 항목별 차이가 있다. 대형 체크포인트·실행파일과 전체 환경변수 덤프는 Git에 넣지 않는다.

## 구현 중 확인·수정한 문제

- Noh 4랭크는 유체 진화와 저장을 마친 뒤 빠른 그림 출력에서 heap 오류가 났다. 기존 `kh_makemap`이 DD 변경 전 부분영역으로 인덱싱했기 때문이다. 전역 영상 좌표, 범위 검사, MPI_MINLOC 최근접 선택으로 고쳤다. 수정 후 1·2·3·4랭크 정상 종료 및 유체 상태 동일을 확인했다. 논문 밀도 그림의 power-cell 렌더러는 바꾸지 않았다.
- `material_profile.sh`와 공용 빌드 진입점에 현재 채택된 부피 역산·고정 원통·검색 범위 정의가 빠져 있었다. 현재 검증 바이너리와 맞췄다. 초기 누락 플래그 빌드는 최종 증거에서 제외했다.
- GPU 기하 오류/검색 부족을 랭크 전체에 공유하여 서로 다른 재시도 결정을 방지한다. 정상 기하의 물리값은 유지된다.
- 강제 거절용 첫 링크는 archive 탐색 순서 때문에 정상 객체를 선택했다. 이 결과는 복구 검사 증거로 쓰지 않는다. 격리 archive를 우선하도록 수정한 `kh_reject_verified_*`에서만 실제 거절 및 복구를 확인했다.
- Ada에서 4랭크를 한 카드에 올린 첫 시도는 기존 프로세스 메모리 점유로 OOM이었다. 다른 작업을 종료하지 않고 Syntax의 여유 A10에서 검증했다.

호스트/CUDA 변경 객체는 실제 컴파일·링크했고 빌드 shell 문법 및 git diff 검사를 통과했다. 이번 검사에는 전체 외부 라이브러리의 clean rebuild나 다중 노드 네트워크 성능 시험은 포함하지 않았다. 신규 checkout의 정식 빌드 진입점은 `NATIVE_PROFILE=material BUILD_LOCAL=1 CUDA_ARCH=<target> Exam/NativeU64/build.sh`다.

## Noh 최신 완료 결과와 다음 단계

최신 전체 종료 결과는 **64², t=0.6**이며, 이번 MPI용 짧은 시험과 구분한다. `common_noh_volume_20261109_v1/comparison_t06/`의 밀도장은 이전 완료 데이터를 그대로 제시한다. 공통 부피 역산 사용 시 평균 충격 반경 0.202403(차가운 기준 0.2), 각방향 반경 RMS 1.47%, 경계 일을 포함한 에너지 상대 잔차 1.47e-14다. 중심 밀도 저하와 방향성 무늬는 남는다. 유한 초기 압력 때문에 차가운 해는 정확한 동일-IC 해가 아니다.

Glass IC가 방향성 무늬를 줄일 가능성은 아직 가설이다. 다음 과학 단계로 regular/glass 동일 Noh 조건의 형상·방사형 프로파일 비교를 제안하며 승인 전 실행하지 않는다. 대규모 MPI 가속을 원하면 전역 제약식의 분산화와 메모리/성능 검증도 별도 범위로 정해야 한다.
