# Thermal-mode-only cache candidate

The earlier two-part constant-configuration cache failed its preregistered eta=.06 **printed numeric-ledger exactness** test, although full native restart records excluding runtime next pointers and all footer bytes were exact. The differing columns were the potential-energy residual and its cumulative value, plus one total-energy drift print. The failed result is preserved in `CACHE_PARITY_ETA006.json`; no threshold was changed. Its short pair's timing is not a replacement for the earlier independent ABBA qualification.

The new isolated candidate retains byte-identical native v2 `Exam/exam.c`, including the original potential diagnostic, and enables only the already developed opt-in process-constant thermal-mode flag cache in `gfs_thermal64.h`. The unchanged CUDA source was rebuilt with the same compiler modules. `THERMAL_ONLY_BUILD.json` pins source and executable hashes. One prior CPU Slurm build attempt on the grammar cluster stopped before building because that cluster has no CUDA 13 module; the isolated build then succeeded on the authorized Ada server with two build threads. Existing running binaries were untouched.

The native eta=.06 test from the preserved t0 IC through the same 20 full steps and roundoff endpoint passes **both complete restart record/footer parity and every printed numeric-ledger line**, as well as frozen executable and no-full-TSV checks. `THERMAL_ONLY_PARITY.json` records the actual test. It ran while the independent Ada simulation shared the GPU, so it yields **no valid speed comparison**. Full ABBA on an unshared GPU, late collision/rollback and H200 tests are still needed before promotion. The active capped branch continues with the baseline v2 executable.
