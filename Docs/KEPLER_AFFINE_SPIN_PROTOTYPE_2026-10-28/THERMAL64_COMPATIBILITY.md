# Thermal64 and moment initialization compatibility

The native source already contains `GfsMomentPayload` and `GFS_MOMENT_INIT_ONLY`: it can initialize affine moments in the existing RK4 scratch prefix, export a tagged full-stride snapshot and exit. It does **not** evolve that moment state. The experimental thermal64 candidate stores authoritative U, V, RHS, tag and RK anchor in five otherwise unused `Stress` fields. The physical storage regions are distinct, but this does not make their energy, initialization or integration contracts compatible: moment initialization changes the float `ie` mirror and exits before `gfs_t64_initialize` runs. In particular, a pre-tagged U64 could remain stale relative to the new moment-derived thermal state.

`Exam/gfs_thermal64_native.inc` now rejects simultaneous positive `GFS_THERMAL64` and `GFS_MOMENT_INIT_ONLY` flags before either initialization proceeds. This is a fail-closed compatibility guard in the repository source, not the implementation of combined spin and thermal64. Thermal64-off moment initialization is unchanged. A harness compiles the actual source dispatch function and checks joint-mode rejection, thermal64-off behavior and continuation of ordinary thermal64 dispatch (`test_thermal64_moment_guard_20261029.py`); non-CUDA syntax compilation of `Exam/exam.c` also succeeds, with existing unrelated format warnings. A CUDA binary/integration test has not yet been run.

The already running Ada binary is a frozen separate executable and does not contain this new repository edit. Existing H200 binaries are also unchanged. For future integration, use a declared versioned particle/checkpoint layout and explicitly reconcile total, affine/rotational and thermal energy, CUDA SoA, MPI ownership/halo, RK stages and complete rollback. The existing `kh_readdata` fallback copies only a common prefix if a stress-file stride differs from the current stress layout; a future stride extension must not rely on that path to preserve the existing thermal64 stress payload. No new restart compatibility or multi-rank behavior is claimed by this guard.
