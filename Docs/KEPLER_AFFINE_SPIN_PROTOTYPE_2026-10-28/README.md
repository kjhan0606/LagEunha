## Local-coordinate moment candidate

`kepler_affine2d_stable.h` preserves the recovered prototype except for computing polygon integrals relative to the first vertex before returning the global centroid. It avoids subtracting two nearly equal global-coordinate raw moments. On a square with stored coordinates (3,3) to (3.0001,3.0001), the [translation test](test_polygon_translation.c) compares against the analytic moment of the actual representable width. The original header had relative area error 9.49e-8 and central-moment error 170.82; the local-coordinate candidate has zero printed area error and 8.88e-16 relative central-moment error. The original header remains unchanged. Both this test and the original analytic tests pass for the candidate, using `gcc -std=c99 -Wall -Wextra -Werror -O2`; the latter was compiled with `-include kepler_affine2d_stable.h`. These are small host-only checks, not a native CUDA implementation, not an evolved spin state, and not a validation of treating polygon area moments as the true mass moments.

The recovered header also has two distinct state representations. Its raw extensive-moment recovery subtracts `H H^T/M` from `Q`; fixing polygon integration alone cannot recover digits already lost when the raw second moment was stored. In the [centered-state precision example](test_centered_state_precision.c), a rigidly rotating cell of width 1e-4 centered at (3,3) gives 8.27e-8 relative angular-velocity error from rounded raw moments, versus zero printed error from the directly stored central moments. Both paths remain present; the test does not change the production data format. Any native spin implementation needs a stable state and flux formulation, including conservative translation, mass flux when weights change, and restart/MPI tests; simply replacing the raw conserved variables with centered ones without deriving their update would not establish conservation. This isolated constructed example does not measure error in the current non-spinning Kepler run.

The width 1e-4 example is deliberately smaller than cells in the current Q1 sample. At the accepted t=.4125 snapshot (`df1eca2b0c341d0c4e61842c6e7ac8ec98ed88e24aea48ef63c1b19f6c57c924`), the minimum `sqrt(stored area)` across 90,352 cells is 0.0145406998, the first percentile is 0.01551664, and none are below 1e-4. Using a **square** of that minimum width at (3,3), [the scale probe](measure_polygon_scale.c) gives relative central-moment error 7.10e-7 with the old formula and 1.11e-16 with the local formula. That constructed square is not an actual cell, and `sqrt(area)` is not a bound on edge lengths or aspect ratio. The active simulation does not use this spin prototype, so these values do not establish an error in its evolution.
